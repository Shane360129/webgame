# 實作狀態：對照查核文件逐條說明

這份表格說明查核文件裡的每一條要求，在本專案裡「做到什麼程度」，
以及**沒有**做到什麼。沒有做到的項目直接寫沒有做到，不用模糊字眼帶過。

對應文件：[`clash-royale-3d-audit.md`](./clash-royale-3d-audit.md)

## 一、最重要的兩個結論（先講不能宣稱的事）

1. **資料沒有齊。** 建置環境的網路政策阻擋了 `royaleapi.github.io`（CONNECT 回 403），
   所以本次**沒有**取得固定版本的完整卡牌匯出檔。專案內所有戰鬥數值都標記
   `statsVerified: false`、`versionDate: null`，遊戲介面上每張卡也會顯示「未驗」徽章。
   這不是完整復刻，也不宣稱與任何平衡版本逐項一致。

2. **沒有官方素材。** 專案不含也不散布任何 Supercell 的模型、貼圖、骨架、動畫、
   音效或介面圖檔。場上與卡面上的每一個角色、建築、法術物件，都是用 three.js 幾何
   在 `public/js/render/models.js` 裡程式化建出來的原創模型。
   詳見 [`licensing-and-assets.md`](./licensing-and-assets.md)。

## 四、查核文件第 7 節「製作順序」的落點

1. **固定參考版本** — 未完成。需要使用者提供要對齊的版本截圖（第 10 節的輸入）。
2. **每角色參考板** — 已有結構（卡片詳情頁的三視圖），但參考來源是本專案自己的模型，不是官方畫面。
3. **八張代表卡 + 雙方塔的模型驗收** — 已超出這個批次：73 張可入卡組的卡 + 5 位冠軍 + 4 種塔兵 + 王塔／公主塔都有模型。
4. **分開驗收模型／材質／骨架／動作／邏輯** — 模型（`models.js`）、材質（`kit.js`）、動作（`animate.js`）、規則（`sim.js`）在程式上就是分開的模組。沒有骨架系統，動作是程序化樞紐旋轉。
5. **鏡頭與規則解耦** — 已完成。`sim.js` 完全不知道鏡頭的存在。
6. **手機操作整合** — 已完成：拖曳部署、部署預覽環、法術範圍圈、可取消拖曳（拖回手牌區放開）、聖水不足即時回饋、三段畫質設定。

## 六、兩個客戶端的實測紀錄

用兩個獨立的瀏覽器 context（各自的 localStorage 玩家 id）對打，觀察到：

| 檢查項 | 結果 |
|---|---|
| 兩人同時排隊是否配到彼此（而非 AI） | 是；雙方的「電腦對手（AI）」標籤都沒有出現 |
| 雙方看到的對手名稱 | A 看到 ClientB、B 看到 ClientA |
| 計時是否同步 | 兩邊同時為 `2:51` |
| 出牌是否只扣出牌方的聖水 | A 出牌後 A 為 5、B 仍為 8 |
| 出的兵是否出現在對手畫面 | 是，且在對手畫面上顯示為紅色（敵方） |
| 雙方是否都把自己看成藍色 | 是（顏色相對於觀看者，不是絕對陣營） |
| 關閉一方的分頁 | 另一方在數秒內顯示「對手斷線中」 |
| 斷線方重新開啟頁面 | 自動接回同一場對戰，計時從 `2:44` 繼續，對方的斷線提示消失 |

回報延遲在本機為 1–3 ms，畫面右下角會即時顯示。
